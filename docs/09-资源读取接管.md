# 09 · 资源读取接管（任务 / GUI / 单位定义）

05 网页层之后，02/03/04 三组（单位、任务、GUI）的译文一直"译了但不显示"。
本文记录根因与最终解法：**在主模块的文件打开函数上做 inline hook，把请求
重定向到 `chs_res/`**。

## 1. 现象与排除

| 层 | 载体 | 实测 |
|---|---|---|
| 主程序硬编码串 | `chs.dict` → hook `sub_544020` | 生效（日志有 `hint:` 行） |
| 内嵌网页 | `chs_web/` → hook `CreateFileA` | 生效（`web: 自检通过`） |
| HPI 内资源（任务/GUI/单位） | 先试 `update/` 覆盖层，再试松散文件 | **都不生效** |

任务 `missions/takmission01_mt.txt` 的英文原文和中文译文都在表里，
但游戏仍显示 `Go north and find the town of Abiad.`；把 843 个改写后的
资源按 VFS 路径铺到游戏根目录后依然无变化。这排除了"翻译没做"和"文件没生成"，
只剩"引擎根本没读这些路径"。

## 2. 根因（IDA）

引擎打开文件的唯一入口是 `sub_53AFF0`（VA `0x53AFF0`，RVA `0x13AFF0`）：

```c
int __stdcall sub_53AFF0(const char* name, const char* mode, int noLoose)
{
    if (!noLoose) {
        if (prefix) { sprintf(buf, "%s%s", prefix, name); f = fopen(buf, mode); }
        if (!f) f = fopen(name, mode);          // ← 松散文件只在这里被尝试
    }
    if (strcmp(mode, "rb")) return 0;
    ... 遍历已加载的 HPI 列表，取优先级最高的同名记录 ...
}
```

`noLoose` 来自 `sub_53B250`：

```c
return sub_53AFF0(name, "rb", sub_53BFD0() != 0);
```

而 `sub_53BFD0()` 返回 `*(fileSystem + 12)` —— 这个字段不是布尔开关，而是
**"Override File Search Path" 字符串**（`sub_53BF50` 设置，`sub_53BFF0` 读取）。
文件系统初始化（`sub_48CBB0`）会按命令行/配置设置它，因此 `noLoose` 恒为非 0，
上面那段 `fopen` 分支永远走不到。

**结论**：`update/` 覆盖层是我们文档里的设计假设；引擎既不认这个目录，
也不会读根目录下的松散同名文件。资源只可能来自 HPI。

## 3. 解法：接管 `sub_53AFF0`

`src/fs_override.cpp`：

1. 启动时扫描 `<游戏目录>\chs_res\`，建立「小写 VFS 路径 → 绝对路径」索引；
2. 在 `0x53AFF0` 装 inline hook（签名 `55 8B EC 81 EC 0C 01 00 00`，
   前 9 字节正好是 `push ebp; mov ebp,esp; sub esp,10Ch`，落在指令边界）；
3. 命中索引且是只读打开时：
   - `_wfopen(副本, L"rb")`
   - `sub_4EB9E0(0x108)` 分配引擎文件对象
   - `sub_5398F0(obj, FILE*, name)` 用引擎自己的构造函数初始化
   - 直接返回该对象（与原生 `fopen` 分支产生的对象完全同类，后续
     vtable 读取/关闭/析构都走引擎原逻辑）
4. 未命中或写模式 → 转发 trampoline，行为与未装 hook 完全一致。

分配与构造放在引擎自己的文件系统锁里完成（`Target` / `dword_66E39C` / `hEvent`
三个全局，递归语义与 `sub_53AFF0` 一致），避免与原生路径并发时踩坏引擎的
空闲链表。`hEvent` 尚未创建时退化为不加锁，防止初始化早期永久等待。

## 4. `chs_res/` 的布局与部署规则

```
<游戏目录>\chs_res\
    missions\takmission01_mt.txt
    guis\visualoptions1.gui
    units\...
    translate\gui_text.tdf
```

- **只从 `build_out/update/` 取**。`build_out/translate/` 是另一套「精简语言槽」
  产物（只有 `[键] { Chinese = ...; }`），与 `update/` 里改写后的完整原文件
  同路径，混用会互相覆盖。
- **多版本按包优先级取一份**：同一 VFS 路径在 `data` / `IPData` / `V2Rocket` /
  `V3Rocket` 里各有一份。引擎按包加载顺序取后者，4.1BB 的修正都在 `V3Rocket`；
  我们同样取优先级最高的版本（实测 211 个：V3Rocket 204、data 5、IPData 1、
  meta 1），否则会把单位数值回退到 4.0。
- `_root/Startup.tdf` 不纳入：根目录已有原版，顶掉会改配置。

当前部署 **1056 个文件**，约 3.2 MB。

## 5. 验证

游戏目录 `tak_chs.log` 里应出现：

```
res: 索引 1056 个资源文件
res: 文件打开 hook 已就绪 @0x0053AFF0
res: 接管 Missions\takmission01_mt.txt      ← 首次命中
...
res: 命中 N 次 / 打开 M 次，失败 0 次        ← 退出时
```

- 若只有「索引」没有「就绪」：签名不匹配（版本不对），hook 未安装；
- 若「就绪」但没有「接管」：引擎没请求这些路径，或请求的路径与索引键不一致
  （大小写/分隔符已在 `NormalizeKey` 里统一，仍不一致就把该行日志发回来）。

## 6. 边界

- 写模式（存档、配置、日志）一律不接管，只转发；
- `chs_res/` 不存在时整个模块直接跳过，游戏行为与未装 DLL 一致；
- 与原版文件的关系：**一个字节都不改**。卸载 = 删掉 `version.dll` 与 `chs_res/`。
