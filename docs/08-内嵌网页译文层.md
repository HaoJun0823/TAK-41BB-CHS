# 08 - 内嵌网页译文层（05 组落地）

05 组是游戏里那 151 个散装 `.htm/.html`：`atlas/` 的世界百科、`Boneyards/` 的
帮助与资料页、`GC/` 的一张活动页。它们**不在任何 HPI 里**，是 GOG 安装时直接
摊在游戏目录里的真实文件，所以：

* `update/` 覆盖层管不到（那是 HPI 虚拟文件系统的补丁目录）；
* 想改就只剩「覆盖原文件」和「改读取路径」两条路，前者违反本工程
  「磁盘游戏文件零改动」的底线。

本层走后者：译文另存到 `chs_web/`，DLL 在 `CreateFileA` 上把请求改道。

```
游戏目录\
    atlas\...\efnian.html        ← 原文件，一个字节不动
    Boneyards\Help\Help12.htm    ← 原文件，一个字节不动
    chs_web\atlas\...\efnian.html      ← 我们的译文副本
    chs_web\Boneyards\Help\Help12.htm
```

## 1. 写回：`tools/apply_web.py`

抽取时 `extract_strings.VisibleText` 把网页按块级标签（`p/div/td/tr/li/br/
h1-h6/center/...`）切成段落，段落序号 `P<i>` 是切块后的自然序号。写回脚本用
**同一套规则**在原文上重放一遍，因此 `P<i>` 能精确落到原始字节区间：

```
<TD><B>Where Do I Begin?</B></TD>
     ↑ 片段1（粗体里的正文）    ↑ 片段2（空白）
```

替换规则：

1. 段落里字符最多的那个文本片段当「主片段」，译文放进去；
2. 其余**非空白**片段清空（保留纯空白片段，避免把换行/缩进也吃掉）；
3. 只动文本区间，标签一个不碰 —— 脚本会断言替换前后标签序列完全一致；
4. 相邻片段可能重叠一个空格（`&nbsp ` 漏写分号时 `html.parser` 会把同一个
   空格算进前后两段），编辑区间按主片段裁剪，不会啃掉译文首尾字节。

写完立刻做**回读校验**：用同一套切块规则再解析一遍产物，要求

* 段落总数不变；
* 未翻译段落逐字不变；
* 翻译段落的可见文本与 `zh` 完全相等（按目标编码解码）。

117 个文件、1097 个写回位置全部通过后才落盘。

编码：网页原文是 iso-8859-1/cp1252 单字节。译文按 **GBK** 写入（与 TDF、
`chs.dict` 一致），同时把 `<meta charset=iso-8859-1>` 改成 `gb2312`，
这样用普通浏览器直接打开 `chs_web/` 里的页面也能正常显示。

```bat
python tools\apply_web.py --check     :: 只校验，不写
python tools\apply_web.py --write     :: 产出 build_out\web\
```

## 2. 读取改道：`src/web_override.cpp`

在游戏主模块的导入表里把 `kernel32!CreateFileA` 换成自己的跳板：

```cpp
HANDLE WINAPI HookedCreateFileA(LPCSTR name, ...) {
    char shadow[MAX_PATH];
    if (MapToShadow(name, shadow))   // 只认 .htm/.html 且落在 atlas/ Boneyards/ GC/
        return g_real(shadow, ...);  // 打开 chs_web 里的译文副本
    return g_real(name, ...);        // 其余原样转发
}
```

要点：

* `KINGDOMS.icd` 只静态导入 `CreateFileA`（没有 `CreateFileW`），一处 IAT 就够；
* 路径先归一化（`/`→`\`、去掉 `.\`、剥掉游戏目录前缀），再按目录白名单判断，
  别的盘符/别的安装目录一律不碰；
* 目标文件不存在就原样转发 —— **没装 `chs_web` 时行为与没打补丁完全一致**；
* 日志逐条记前 60 次命中，未命中页面记前 20 次，退出时给总数；
* 启动时做一次自检：把 `.\boneyards\Help\Help1.htm` 走一遍匹配，日志里能看到
  匹配到的实际路径，避免「装上了但路径没对上」只能靠猜。

## 3. 实机状态（要如实说明）

已经验证的：

```
web: CreateFileA 已接管，译文目录 I:\...\chs_web
web: 自检通过，示例 I:\...\chs_web\boneyards\Help\Help1.htm
```

**没能验证的**：这些页面在单机流程里没有入口。`Boneyards/Help/*.htm` 属于
联机大厅里的帮助控制台（`guis/bynniconsole.gui` 里那个 `Help` 按钮），
`atlas/` 的百科页由 Boneyards 的 Earthfile 站点调起。Boneyards 服务 2002 年
就停了，2006 年连站点都下线，实机点进去只会看到：

```
A FULL UPDATE IS REQUIRED [Boneyards auto-update]
PACKAGE UPDATE FAILED - PROBLEMS ACCESSING SOURCE URI
```

所以这一层目前是「**基础设施就位、内容已译好、入口不可达**」：一旦有人做出
Boneyards 私服或把帮助控制台单独调起来，`chs_web/` 会立即生效。另外，网页
渲染器是否吃 GBK 也还没实测（页面走的是引擎自己的 HTML 控件，不是 IE）。

## 4. 已知取舍

| 项 | 说明 |
|---|---|
| 段内行内排版 | 一段里既有粗体又有正文时，译文会整段落在字符最多的片段里，粗体范围可能不再对应原文（可读性不受影响） |
| 图片/链接 | `<img>`、`<a href>` 全部原样保留；链接文字被译后仍然可点 |
| 表格布局 | 只替换 `td` 里的文字，`width/valign` 等属性不动 |
| 页面标题 | `<title>` 在 `<head>` 里，按抽取规则跳过（不译） |
| 不可达页面 | Boneyards 相关页面在离线环境打不开，属服务停运，不是本层的问题 |

## 5. 部署

`tools/deploy.py` 会把 `build_out/web/**` 复制到 `<游戏目录>\chs_web\**`，
并写进 `.tak_chs_files.txt`；撤回时按清单精确删除，`atlas/`、`Boneyards/`、
`GC/` 原文件始终不动。

```bat
python tools\apply_web.py --write
python tools\deploy.py --game "<游戏目录>" --apply
```
